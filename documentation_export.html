3. Backend Architecture & Package Structure

The backend is situated inside /backend and managed via Apache Maven. It strictly uses Java 17 features including enhanced switch expressions, clean records, and modern Spring Boot 3 conventions.

3.1 Core Domain Entities (com.bank.securebanking.entity)

  • User.java: Represents a bank customer or staff member. Maps to the users table. Contains fullName, unique email, BCrypt password, phone, role (ROLE_CUSTOMER or ROLE_ADMIN), and a one-to-many relationship with Account.
  • Account.java: Represents a financial ledger account. Maps to the accounts table. Generates unique 10-digit account numbers (e.g. 1001002026), holds an IFSC code (SBMS0001024), accountType (SAVINGS, CURRENT, FIXED_DEPOSIT), current balance (BigDecimal(15,2)), and status (ACTIVE, FROZEN, CLOSED).
  • Transaction.java: Represents an individual ledger entry. Maps to the transactions table. Contains a unique reference UTR number (e.g. TRF2609030003), transactionType (DEPOSIT, WITHDRAWAL, TRANSFER_SEND, TRANSFER_RECEIVE), amount, postBalance snapshot, and timestamp.

3.2 Security Engine & JWT Infrastructure (com.bank.securebanking.security)

The security layer is decoupled and stateless, complying with OWASP financial application guidelines:

JWT Processing Lifecycle
  1. Authentication: AuthController receives credentials and delegates to AuthenticationManager which invokes UserDetailsServiceImpl.
  2. Token Generation: JwtUtils.java encodes subject email, user ID, full name, and expiration time using HMAC-SHA256 with a 256-bit secret key.
  3. Request Filtering: For subsequent requests, AuthTokenFilter.java extracts Authorization: Bearer <token>, checks integrity via Jwts.parser().verifyWith(key), and loads user permissions into the SecurityContext.
  4. Unauthorized Trapping: If expired or missing, AuthEntryPointJwt.java returns a structured JSON 401 error.
// Security Configuration Snippet (SecurityConfig.java)
@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http
        .cors(cors -> cors.configurationSource(corsConfigurationSource()))
        .csrf(csrf -> csrf.disable())
        .exceptionHandling(ex -> ex.authenticationEntryPoint(unauthorizedHandler))
        .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/api/auth/**", "/api/health", "/h2-console/**").permitAll()
            .requestMatchers("/api/admin/**").hasAnyAuthority("ROLE_ADMIN", "ROLE_BANKER")
            .anyRequest().authenticated()
        );
    http.authenticationProvider(authenticationProvider());
    http.addFilterBefore(authTokenFilter, UsernamePasswordAuthenticationFilter.class);
    return http.build();
}

4. REST API Contract & Endpoints

All REST APIs adhere to uniform request and response contracts wrapped inside the generic ApiResponse<T> envelope.

4.1 Authentication Endpoints (/api/auth)

Method & Endpoint Payload Parameters Response Data Description
POST /api/auth/register fullName, email, password, phone, accountType, initialDeposit AuthResponse (JWT Token, User ID, Account Number) Onboards new customer & automatically provisions an active bank account.
POST /api/auth/login email, password AuthResponse (JWT Token, User ID, Role) Validates credentials against BCrypt hash; issues 24-hour Bearer token.
GET /api/auth/me None (Requires Bearer <token>) User profile JSON (ID, Full Name, Email, Phone, Role) Retrieves the current authenticated profile.

4.2 Account Management Endpoints (/api/accounts)

Method & Endpoint Access Level Response Data Description
GET /api/accounts/my-accounts Customer / Admin List<AccountDto> Retrieves all accounts belonging to the authenticated user.
GET /api/accounts/{accountNumber} Owner / Admin AccountDto Retrieves specific balance, IFSC code, and account status.
GET /api/accounts/verify/{accountNumber} Authenticated AccountDto (Safe) Validates recipient account; returns recipient customer name for confirmation.
POST /api/accounts/new Authenticated AccountDto Generates additional Savings, Current, or Fixed Deposit accounts.
PATCH /api/accounts/{accountNumber}/status ROLE_ADMIN AccountDto Updates account lifecycle state (ACTIVE, FROZEN, CLOSED).

4.3 Transaction Operations Endpoints (/api/transactions)

Method & Endpoint Payload Parameters Response Data Description
POST /api/transactions/deposit accountNumber, amount, description TransactionDto Credits funds to active account; records ledger credit entry.
POST /api/transactions/withdraw accountNumber, amount, description TransactionDto Debits funds after balance verification; simulates ATM cash payout.
POST /api/transactions/transfer fromAccountNumber, toAccountNumber, amount, description TransactionDto Atomic P2P transfer; debits sender, credits receiver, logs dual UTRs.
GET /api/transactions/history/{acc} Account Owner / Admin List<TransactionDto> Returns chronological ledger history sorted newest first.
GET /api/transactions/receipt/{ref} Authenticated TransactionDto Retrieves individual transaction receipt by UTR reference code.

4.4 Bank Administration Endpoints (/api/admin)

Method & Endpoint Required Role Description
GET /api/admin/dashboard ROLE_ADMIN Returns aggregate bank reserves, total customers, accounts, credit/debit volume.
GET /api/admin/accounts ROLE_ADMIN Returns complete registry of all customer accounts in the institution.
GET /api/admin/transactions ROLE_ADMIN Returns immutable global audit log of all transactions system-wide.

8. Technical Interview Preparation & Talking Points

💡 How to present this project during a technical interview
Highlight the architectural decisions, security considerations, and edge cases you tackled rather than just listing features.

Q1: "How did you ensure fund transfers don't result in dirty reads or double-spending?"

Answer: "In TransactionService, I annotated the transfer method with @Transactional(isolation = Isolation.REPEATABLE_READ). This ensures that when querying the sender's balance, no concurrent transaction can modify the record during execution. The debit and credit legs occur within the exact same database transaction boundary. If an exception occurs—such as a network timeout or insufficient funds—the entire transaction rolls back cleanly, maintaining ACID compliance."

Q2: "How is security implemented without session state?"

Answer: "I implemented a stateless JWT authentication model using Spring Security 6 and JJWT 0.12.6. When a user logs in, their password is validated using BCrypt. Upon success, a signed HMAC-SHA256 JWT is returned containing their identity and role authorities. An AuthTokenFilter subclasses OncePerRequestFilter to inspect the Bearer token on every request, validate its cryptographic signature and expiration, and establish the user's Authentication in the SecurityContextHolder."

Q3: "How does the frontend handle token expiration and authorization errors?"

Answer: "The React frontend uses a centralized API client in api.js. If a response returns HTTP 401 Unauthorized or 403 Forbidden, it automatically triggers a logout callback that purges localStorage tokens and pops up the LoginModal, notifying the user gracefully with a toast notification rather than breaking the UI state."
